Capture is the first step in browser-use. Four ways to turn a live page into something a model can act on — only options 3 and 4 scale for vision agents. Token numbers are estimated LLM context (options 1–2) or a fixed VLA vision budget (options 3–4).

I didn’t ship this path — selectors rot on every deploy, and iframe traversal hits security walls.

Option 3 — Screenshot via clone libs → VLA

fast enough for voice ~2px text drift (FO vs compositor)
→ ~290–672 vision tokens (fixed budget)

What I ship today in browser-use-wasm. html2canvas redraws procedurally; SnapDOM optimizes the foreignObject path — still not the browser’s native paint engine.

Option 4 — HTML-in-Canvas (native spec) → VLA
<canvas layoutsubtree>
  <div id="capture-target">…live page…</div>
</canvas>

canvas.onpaint = () => {
  ctx.drawElementImage(capture_target, 0, 0);
  // compositor paint — same path as live page
};
Chrome flag · not drop-in yet

WICG HTML-in-Canvas (★3.6k) — drawElementImage() records the browser’s painted output, bypassing SVG foreignObject. Enable with chrome://flags/#canvas-draw-element.

Options 1–2: tokens ≈ characters ÷ 3.5 (live outerHTML + computed stylesheet rules). Options 3–4: same fixed ShowUI vision-token budget (~290–672), regardless of page size — only the capture engine differs. WebGPU/WASM text models often cap at ~2k–4k context (transformers.js #1697).

JavaScript has had DOM-to-screenshot libraries for years. They fall into three families — only one path uses the browser compositor today, and that one still needs a Chrome flag.

Why SnapDOM: near-instantaneous capture (<10ms many times for complex webpages), no complex DOM traversals. Tradeoff: layout composition within an SVG foreignObject is full of quirks.

Font metric mirror plugin

Partial

Canvas-measured sizes, fake @font-face rules, forced font-size/line-height on clone. Helps a little on system-ui; does not kill the ~2px canvas jump. SVG layout was already close — raster step is where it breaks (tonsky on font-size).

deviceBackingSize — floor / round / ceil

No fix

Tried floor, round, and ceil on fractional device heights — see the rounding card. None fixed medY drift; ceil sometimes hung capture.

Genetic search — 25,000 capture recipes

No fix

Mutate plugins, CSS flags, timing knobs; score medY + fullPage. Kept rediscovering the same Pareto cliff and “cheating” mutants (landmark fix, broken full-page) — not a real fix.

CSS contain / isolation on clone

No fix

contain: strict, isolation: isolate — stacking-context experiments. Same plateau.

Root cause — three-layer ink comparison

Found it

Overlay live page, SVG, and canvas; match ink positions letter-by-letter. Live ≈ SVG; canvas raster diverges ~2px. Fix when HTML-in-Canvas lands — or let authors opt into predictable fonts.
