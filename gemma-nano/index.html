Gemini Nano: The Future of Private Browser Automation

June 13, 2026 • By Paul Dufour • Architecture

Disclaimer: This demo uses Chrome’s built-in on-device model through the Prompt API-it is not a fine-tuned vision-language-action (VLA) model like ShowUI-2B. Screenshot grounding, click accuracy, and latency vary a lot by goal, page layout, and your machine. Treat results as experimental; for tuned GUI automation, use the ShowUI operator instead.

Browser automation has traditionally relied on heavy server-side infrastructure. With Gemini Nano and the Chrome Prompt API, we enable 100% on-device, private browser control. Your screenshots and private data never leave your computer.

Live demo

Try it

You type a goal. Chrome screenshots the page in the iframe, Gemini reads the image locally, picks an action (click, type, etc.), and the browser executes it on the real page. No server. Try the default: type Joe in the email field → Run.

One-time Chrome setup

  1. Browser: Chrome 131+ (Dev/Canary for latest multimodal).
  2. Perf Bypass: chrome://flags/#optimization-guide-on-device-model → Enabled BypassPerfRequirement.
  3. Prompt API: chrome://flags/#prompt-api-for-gemini-nano (+ multimodal flag if listed).
  4. HTML-in-Canvas: chrome://flags/#canvas-draw-element → Enabled (Step 2 drawElementImage capture).
  5. Update: chrome://components → Optimization Guide On Device Model.

How it works

Step by step

The demo above runs all three stages in one shot. Below you can run each piece in isolation.

Step 1 - Initialize the multimodal session

The Chrome Prompt API is the modern entry point for on-device AI. We resolve the API across various namespaces to find the LanguageModel surface: 

const ai = window.LanguageModel || window.ai?.languageModel;
if (!ai) throw new Error('LanguageModel not found');

const session = await ai.create({
  expectedInputs: [{ type: 'text' }, { type: 'image' }],
  temperature: 0,
});
session.destroy?.();
return 'Multimodal session created';

Step 2 - Capture the page with drawElementImage

Under the hood, Chrome rasterizes DOM through the experimental HTML-in-Canvas API: canvas.getContext('2d').drawElementImage(element, x, y) paints a live subtree into a bitmap using the browser layout engine (no screenshot server, no html2canvas-style SVG hack). chrome://flags/#canvas-draw-element must be on.

SnapDOM is just a wrapper around that call: clone the target, inline computed styles and fonts, size the canvas, then invoke drawElementImage and hand you the HTMLCanvasElement. The checkout strip below is what gets rasterized; your code only needs SnapDOM:

// SnapDOM → clone + inline styles/fonts → drawElementImage → canvas
const target = document.getElementById('snippet-stage');
const canvas = await snapdom.toCanvas(target, {
  width: target.offsetWidth,
  height: target.offsetHeight,
  dpr: Math.min(2, devicePixelRatio || 1),
  embedFonts: true,
});
return canvas;

Step 3 - Ground coordinates and click

Step 3 wires it together: SnapDOM (same drawElementImage path) screenshots the live iframe (#capture-target), then the Chrome Prompt API (LanguageModel, session.prompt) reads that JPEG and returns [x, y]. We click at that point in the iframe. 

const frame = document.getElementById('browse-frame');
const doc = frame.contentDocument;
const stage = doc.getElementById('capture-target');
if (!doc || !stage) {
  throw new Error('Demo page not loaded yet - wait for the checkout preview above');
}

// Chrome Prompt API (on-device Gemini Nano)
const ai = window.LanguageModel || window.ai?.languageModel;
if (!ai) throw new Error('LanguageModel not found');

const session = await ai.create({
  expectedInputs: [{ type: 'text' }, { type: 'image' }],
  expectedOutputs: [{ type: 'text' }],
  temperature: 0,
  topK: 1,
});

// Drop live-demo pointer overlay so SnapDOM does not photograph it
doc.getElementById('agent-grounding-layer')?.remove();

// Screenshot → JPEG (vision input for Prompt API)
const canvas = await snapdom.toCanvas(stage, {
  width: stage.offsetWidth,
  height: stage.offsetHeight,
  dpr: Math.min(2, devicePixelRatio || 1),
  embedFonts: true,
});

const jpeg = await new Promise((resolve, reject) => {
  canvas.toBlob(
    (blob) => (blob ? resolve(blob) : reject(new Error('JPEG encode failed'))),
    'image/jpeg',
    0.92
  );
});

const navSystem = `You are an assistant trained to navigate the web screen.
Given a task instruction, a screen observation, and an action history sequence,
output the next action and wait for the next observation.
Format the action as: {'action': 'CLICK', 'value': None, 'position': [x,y]}
Position is 0-1 on the screenshot.`;

const t0 = performance.now();
const raw = await session.prompt([
  {
    role: 'user',
    content: [
      { type: 'text', value: navSystem },
      { type: 'text', value: 'Task: click Submit' },
      { type: 'image', value: jpeg },
    ],
  },
  { role: 'assistant', content: "{'action':", prefix: true },
]);
session.destroy?.();

let text = String(raw ?? '').trim();
if (text && !text.startsWith("{'action':") && !text.startsWith('{"action":')) {
  text = `{'action': ${text}`;
}

const vision = { width: canvas.width, height: canvas.height };
let point = null;
for (const match of text.matchAll(/\{[^{}]*\}/g)) {
  const jsonish = match[0].replace(/'/g, '"').replace(/\bNone\b/g, 'null');
  let parsed;
  try {
    parsed = JSON.parse(jsonish);
  } catch {
    continue;
  }
  const pos = parsed.position;
  if (!Array.isArray(pos) || pos.length < 2) continue;
  const x = Number(pos[0]);
  const y = Number(pos[1]);
  if (!Number.isFinite(x) || !Number.isFinite(y)) continue;
  const clamp = (v) => Math.min(1, Math.max(0, v));
  if (x <= 1 && y <= 1) point = { x: clamp(x), y: clamp(y) };
  else if (x <= 100 && y <= 100) point = { x: clamp(x / 100), y: clamp(y / 100) };
  else if (x <= vision.width && y <= vision.height) {
    point = { x: clamp(x / vision.width), y: clamp(y / vision.height) };
  }
  if (point) break;
}
if (!point) throw new Error('No [x,y] in model output: ' + (text || '(empty)'));

const rect = stage.getBoundingClientRect();
const el = doc.elementFromPoint(
  rect.left + point.x * rect.width,
  rect.top + point.y * rect.height
);
if (!el) throw new Error('elementFromPoint returned null');
el.click();

const submit = doc.getElementById('btn-submit');
const hitSubmit = el === submit || (submit && submit.contains(el));

return {
  canvas,
  point,
  text,
  inferMs: Math.round(performance.now() - t0),
  hitSubmit,
  clickedLabel: el.textContent?.trim() || 'element',
};

Hardware constraints

Gemini Nano uses your computer's hardware (like your graphics card) to "think" locally. Key constraints include:

  • Video Memory (VRAM): Requires ~2GB of dedicated memory. On older computers, the browser might be slow or unable to start the AI.
  • Model Compression: To save space, the model is "compressed" (quantized). While very fast, it can sometimes be slightly off when clicking tiny buttons.
